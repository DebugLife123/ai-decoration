# 业务集成发布检查

已验证基线：main `ee22c45`，业务分支 `ad0acb9`。这是本地集成版本，不是已部署版本。

1. 恢复内网后重新 fetch，确认 `origin/main` 的新提交没有被覆盖。记录线上前后端镜像、数据库版本、文件卷和旧积分文件。备份数据库与上传文件，并演练恢复。
2. 在生产数据库副本验证 Flyway 历史、校验和及报价唯一键。保留已有 V20，不清库、不手改历史。历史公开材料保持可见，新报价和修改后的报价必须送审。
3. 发布前暂停生成、等待在途任务结束，按用户核对旧账本余额、计划、流水和未结算预扣。新表用整数分（100 = 1 积分）。不要重复赠送。新用户自动得 3 积分，旧用户不能靠注册触发器迁移。没有验证迁移和对账结果之前不要切换网关。
4. 为后端和 AI 网关注入相同的高熵 `CREDIT_GATEWAY_SECRET`（最少 32 字符），仅用服务端变量，配置 `BACKEND_URL`。网络层限制 `/internal/wallet/` 的访问；不要写进镜像、VITE_ 变量或日志。核对预扣长期未结算的操作；重试前验证实际生成结果。
5. 当前默认 CI 仅发布前端，不能直接使用。先在预发布部署同一提交的 Java 后端、数据库迁移和网关，再发布前端。真实支付未接入，企业订单采用管理员沙箱确认。
6. 实测存量用户登录、预算进入工作台、投稿驳回及重提、审核后广场可见、企业报价及询价。再实测真实模型识图、全屋生成、部分失败重试、画布局部编辑，核对用户余额和管理员流水。断开浏览器和重启网关需验证在途账务可恢复。
7. 切换后核对运行镜像与提交 SHA。回滚保持写入冻结，核对新账再决定账本切换，不可仅回滚前端或直接恢复有新写入的数据库。
