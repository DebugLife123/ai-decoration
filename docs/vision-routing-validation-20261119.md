# 识图连接与候选模型路由验收（2026-11-19）

## 发布行为

- AI 请求使用独立 Undici 连接池，连接握手期限 30 秒，复用连接；不改变登录和数据库传输。
- 生产识图顺序：`gpt-6.1-sol` → `gpt-6-astra` → `gpt-6.2-sol`。候选通过服务端识图密钥的 `/v1/models` 确认可见并实测。
- `AI_VISION_FALLBACK_MODELS=gpt-6-astra,gpt-6.2-sol`，最多两个备选，去重。配置为空时只使用主模型；不自动选择未经验证的新模型。
- `AI_ANALYSIS_TIMEOUT_MS=120000`，`AI_ANALYSIS_TOTAL_TIMEOUT_MS=300000`。每个候选最多调用一次，最后候选只使用剩余总时间。
- 连接错误、超时、403/404/408/429/500/502/503/504/524、空结果或无效空间 JSON 触发下一候选。401 和一般输入错误不切换。
- 同一请求保留 requestId，记录切换原因、实际使用模型及耗时，不记录密钥或图像内容。户型图、CAD 导出图、实景分析使用此路由；生图、图片编辑和复核不进入此路由。
- 候选切换发生在原有积分预扣与结算内部，不按候选次数重复扣用户积分。上游计费仍由模型服务商决定。

## 服务器实测

使用生产相同的识图密钥和模型地址，在隔离候选容器及测试数据库执行。测试图有 11 个文字标注区域，使用业务原有提示词。

| 模型 | 首轮耗时 | 恢复服务器环境后复测 | 结果 |
| --- | --- | --- | --- |
| gpt-6.1-sol | 64.8 秒 | 业务接口 53.8、58.0 秒 | 11 个标注区域 |
| gpt-6-astra | 81.5 秒 | 38.8 秒；路由兜底 37.9 秒 | 11 个标注区域 |
| gpt-6.2-sol | 83.4 秒 | 44.2 秒 | 11 个标注区域 |
| gpt-5.6-sol | 85.0 秒 | 未重复 | 11 个标注区域 |
| claude-sonnet-4-6 | 65.5 秒后失败 | 未重复 | socket 中断及连接超时 |
| claude-fable-5 | 67.9 秒后失败 | 未重复 | socket 中断及连接超时 |
| grok-4.7 | 61.7 秒后失败 | 未重复 | 连接超时 |

这些是小样本时延与标注覆盖检查，不构成长周期稳定性或空间几何准确率结论。所有候选共用 API 网关，连接失败不能直接归因于模型。复测期间服务器 WSL/Docker 环境曾重启，期间三个 GPT 请求连接中断，未计入性能比较；生产恢复健康后重新验证。

## 验证结果

- 慢 TLS 握手对照：默认 fetch 10.74 秒连接超时；新连接器 11.53 秒成功，复用请求 2 毫秒。
- 连接池与路由测试 9 项通过；既有识图重试和生图重试测试 2 项通过。
- `npm run build` 通过；仅现有 bundle 大小提示。
- 两次真实业务识图均成功：测试账户积分 3 → 1，pendingHolds=0。
- 注入主模型 503，第二模型发起真实 AI 请求并成功：11 个空间，积分 3 → 2，pendingHolds=0。
- 无数据库迁移；仅更新前端/AI 网关服务，沿用原 Java 后端镜像和数据卷。

30 秒连接期限与多模型候选降低短暂故障影响，但同一上游域名完全不可达时，切换模型仍可能全部失败。图像编辑响应超时不属于本次修复范围。
