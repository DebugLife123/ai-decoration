# 预算该有哪些板块（据实模板校准）

> 校准对象：`D:\开发\预算模板表.xlsx`（实为 BIFF8 .xls，带打开密码，8 个工作表）。
> 校准目标：`docs/BUDGET_MODEL.md` 里那套「6 个分项」的划分来自行业经验，不是真实装企口径。
> 本文是据实模板给出的板块结构 + 对原方案的修改清单。

---

## 0. 一句话结论

真实装企预算不是「6 个分项，每项一个元/㎡」，而是：

```
两层清单  ×  两种计价模式  +  四个非计价区
```

| 层 | 内容 | 计价单位 |
|---|---|---|
| 第一层 建安预算 | 7 个分部，做「基础装修」 | 数量 ×（基材单价 + 人工单价） |
| 第二层 主材项目 | 9 个分部，做「材料代购」 | 同上，但**数量是引用建安用量的** |
| 模式 A 清单式 | 建安 + 主材，逐项报价 | 元/单位 |
| 模式 B 套餐式 | 全包外部，按面积打包 | **元/㎡** |
| 非计价区 | 赠送项目、客户自购材料、基础材料配置、编制说明 | 不计入合计 |

原方案的 6 分项把这两层拍平成了一个维度，**漏掉「家具制作」和「其他措施」两个独立分部**，也漏掉了「套餐式」这种计价模式。这是本文要修的主要问题。

### 2.1 关键设计：主材数量引用建安用量

```
瓷砖      D18 = 建安预算!D13 * 1.08
木地板    D6  = 建安预算!D12 * 1.05
集成吊顶  D83 = 建安预算!D13 * 1.05
```

即**主材用量 = 对应基础项目的用量 × 损耗系数**（瓷砖 1.08，地板与吊顶 1.05）。

这直接印证了 `BUDGET_MODEL.md` §3.2 的 `workload_factors.waste_rate` 是必要的，而且系数该取 5% / 8%，不是 12%。

## 3. 合计口径（必须照抄，原方案这里是错的）

工作表 `建安预算` A348-A351：

```
G348 工程直接费   = G346+G328+G273+G243+G204+G133+G94     ← 建安 7 个分部小计相加
G349 主材直接费   = 主材项目!G104                          ← 主材 9 个分部小计相加
G350 工程管理费   = (G348 + G349) * 0.1                    ← 10%
G351 工程总造价   = G348 + G350                            ← 直接费 + 管理费
```

**管理费是 10%，不是原方案写的 12%。**

另有三项「单独收取，不计入合同造价」，放在 B353-B355：

| 项 | 算式 | 备注 |
|---|---|---|
| 税金 | 总造价 × 5.36% | 税前报价，代办时代收 |
| 远程费用 | 总造价 × 2%（县城 5%） | |
| 楼霸沙霸费用 | 无固定公式 | 按现场实际 |

## 4. 从模板里抄出来的四条计算规则

这四条原方案里一条都没有，但直接决定预算能不能算对。

### 4.1 材料与人工是两列，不是一个合并单价

每行都是 `数量 ×（基材单价 + 人工单价）`。这和我们现有表结构刚好对得上：

- `material_quotes(price, unit)` → 对应 E 列
- `labor_quotes(price, unit)` → 对应 F 列

**所以合成一个「综合单价」是错的**，会把「材料降 10%」和「人工涨 10%」抵消掉，用户看不出钱花在哪。
预算响应里每个分项必须能拆成 `materialCost` / `laborCost` 两个数。

### 4.2 最低计量规则（不足按最小量计）

散落在 H 列备注里，共 7 条：

| 项目 | 规则 |
|---|---|
| 柜门 | 单扇不足 0.4㎡ 按 0.4㎡ 计算 |
| 柜顶封板 | 单处不足 1㎡ 按 1㎡ 计算 |
| 水表移位 | 不足 1000mm 按 1000mm 计算 |
| 厨房推拉门 | 单页不足 1.6㎡ 按 1.6㎡ 结算 |
| 清漆 | 不足 20㎡ 按 20㎡ 计量 |
| 其余油漆 | 不足 15㎡ 按 15㎡ 计量 |
| **水电改造** | **面积不足 85㎡ 按 85㎡ 计算** |
| **套餐报价** | **面积不足 90㎡ 按 90㎡ 计算** |

后两条是全局兜底，对小户型影响很大（60㎡ 的房子水电仍按 85㎡ 收费）。

### 4.3 三种面积口径并存，不能混用

| 口径 | 用途 | 来源 |
|---|---|---|
| 建筑面积 | 用户现在输入的量 | `projects.area` |
| 套内面积 | 实际铺装、涂装的计算基数 | 建筑面积 × 得房率 |
| **实测框架面积** | 套餐式计价基数 | 室内面积 + 外墙 240mm |

模板 `编制说明` ⑵ 明确写：「全包模式预算按实测面积计费，实测面积 = 室内面积 + 外墙 240mm」。
`编制说明` ⑶ 墙漆口径：「**周长 × 层高 − 门窗洞各半 − 家具面积**」，吊顶按**展开面积**算。
—— 这比原方案 §2.2 的「墙面面积 = 套内面积 × 2.35~2.75」更精确，但需要用户输入层高。

### 4.4 超高、超层、远程的附加费

| 场景 | 规则 |
|---|---|
| 层高 > 3500mm | 超高部分按实测面积另收（60 元/㎡） |
| 无电梯 | 材料上楼 600 元/层、模具搬运按实际层数 |
| 有电梯 | 材料上楼 100 元/层、模具搬运按两层计 |
| 复式 / 架空层 | 各加 1 层 |
| 远程 | 总造价 2%，县城 5% |
| 材料货运 | 基础造价 × 1%（含在措施工程里） |

## 5. 原方案 6 分项 vs 模板真实板块

| 原方案 | 模板对应 | 结论 |
|---|---|---|
| `DEMOLITION` 拆改与水电 | 五、水电改造及安装 + 六、结构改造 | ❌ 两个独立分部被合成一个，占比被低估 |
| `MASONRY` 泥瓦与防水 | 一、地面工程（部分） + 三、墙面及门窗（部分） | ⚠️ 按工序分 vs 按部位分，维度不一致 |
| `WALL` 墙顶面与涂装 | 二、顶面工程 + 三、墙面及门窗 | ⚠️ 同上 |
| `GROUND` 地面铺装 | 一、地面工程 | ✅ 基本对应 |
| `KITCHEN` 厨卫与定制 | 主材四、卫浴洁具 + 六、橱柜 + 七、集成吊顶 + 五、合金门 | ❌ 4 个主材分部被压成 1 项 |
| `OVERHEAD` 安装辅料与管理 | 七、其他措施工程 + 管理费 10% | ⚠️ 把「措施费」和「管理费」混在一起了 |
| — | **四、家具制作工程** | ❌ **完全缺失**（柜体 350+100/㎡，占比不小） |
| — | 主材一/二/三/八/九 | ❌ 全部缺失 |
| — | 套餐式（全包外部） | ❌ **完全缺失**这种计价模式 |

**最严重的三处**：
1. 漏了「家具制作工程」——这是装修预算里最容易超支的部分
2. 把「措施费」（成品保护、垃圾清运、上楼、防开裂）当成管理费的一部分，导致小户型严重低估
3. 没有「套餐式」这个模式，而真实装企**一半以上的单子走套餐**

## 6. 建议的平台板块（对齐模板，但保持可算）

不能把模板 16 个分部照搬，因为用户只给面积，给不出「几扇柜门」「几米包管」。
折中方案：**保留 9 个可算板块**，每块下面挂多个模板分部。

| 平台板块 key | 显示名 | 对应模板分部 | 计算基准 |
|---|---|---|---|
| `GROUND` | 地面工程 | 建安一 | 套内面积 × 铺装率 |
| `CEILING` | 顶面工程 | 建安二 | 套内面积 × 吊顶率 |
| `WALL_DOOR` | 墙面与门窗 | 建安三 | 墙面面积（周长×层高−门窗半−家具） |
| `CARPENTRY` | 家具制作 | 建安四 | 延米（按户型推定柜体长度） |
| `PLUMBING_ELEC` | 水电改造 | 建安五 | 套内面积（最低 85㎡ 兜底） |
| `STRUCTURE` | 结构改造 | 建安六 | 拆改面积（默认 0，需用户勾选） |
| `MEASURES` | 措施与杂费 | 建安七 | 按直接费百分比 + 层数 |
| `MAIN_MATERIAL` | 主材（地板/瓷砖/石材/门） | 主材一/二/三/五/九 | 引用上游板块用量 × 损耗 |
| `FIXTURE` | 设备与洁具（卫浴/吊顶/开关/橱柜） | 主材四/六/七/八 | 按套/按户/按延米 |

管理费单独一项，**费率 10%**，不再混进 `MEASURES`。

## 7. 还需要补的三个模型概念

### 7.1 计价模式（`pricing_mode`）

```
LIST     清单式：建安 + 主材逐项报价        ← 现在的 BUDGET_MODEL.md 只支持这个
PACKAGE  套餐式：实测面积 × 套餐单价 + 管理费  ← 模板里「全包外部」就是这种
```

套餐式必须支持：`套餐单价(元/㎡) × max(实测面积, 90㎡) + 增项 + 管理费 10%`。

### 7.2 项目性质（`item_nature`）

模板有「赠送项目」和「客户自购材料项目」两个整表，共 12 + 12 类：

```
INCLUDED        计价项（进合计）
GIFT            赠送项（进合同、不进金额，但要列出来让客户知道值多少钱）
OWNER_SUPPLIED  客户自购（不计价，但要提醒「不包含在报价内」）
```

第三类最容易引发纠纷——「全房灯具」在模板里明确是客户自购，如果我们默认算进预算，交付时就会扯皮。

### 7.3 复合单位（原方案 6 类枚举不够）

实测单位分布（去重后 20 种）：

| 类别 | 原始写法 | 建议 kind |
|---|---|---|
| 面积 | `m2` `㎡` `平方米` `平米` | `SQM` |
| 长度 | `m` `米` | `LM` |
| 件数 | `樘` `个` `件` `块` `片` `扇` `盏` `根` | `PIECE` |
| 套/项 | `套` `项` `组` | `SET` |
| 包装 | `桶` `袋` `箱` `包` | `PACKAGE` |
| 工日 | `工日` `人日` `天` | `DAY` |
| **复合：按级** | `m/级`（楼梯踏步） | `LM_PER_LEVEL` |
| **复合：按层** | `m2/层`（垃圾清运）、`m/层`（上楼） | `SQM_PER_FLOOR` / `LM_PER_FLOOR` |
| **复合：按厚度** | `cm/m2`（落差找平） | `CM_PER_SQM` |
| **复合：延米套** | `套米`（橱柜） | `SET_LM` |
| **计数：按户/间** | `户` `间` | `HOUSE` / `ROOM` |

原方案的 6 类**只能覆盖前面 6 行**，后面 5 行（复合单位）全部会落到 `UNKNOWN` 被排除。而这些恰恰是措施费、楼梯、找平这些真实存在的项目。

## 8. 模板自身的缺陷（不要照抄）

| 位置 | 问题 |
|---|---|
| `全包外部!G50` | `=#REF!+G38+#REF!` —— 公式已损坏（增减项目合计） |
| `全包外部!G49` | 公式 `=1098*B3`，但 H49 文案写「按 898 元/㎡计费」—— 898 与 1098 不一致 |
| `建安预算!G351` | 公式 `=G348+G350`，但 `G348` 已含 `主材项目!G104`，注释却写「直接费 + 管理费」—— 语义含糊 |

这三处说明模板是长期手工维护的，改过价格没改文案。**我们照抄的是结构和规则，不是数值。**

## 9. 对 `BUDGET_MODEL.md` 的修改清单

| # | 原方案 | 改成 |
|---|---|---|
| 1 | 6 个分项 | 9 个板块（§6 的表） |
| 2 | 管理费 12% | **管理费 10%** |
| 3 | 单价 = P25/P75 综合单价 | 拆成 `materialPrice` 与 `laborPrice` 两路，各自算区间 |
| 4 | 单位 6 类 | 11 类（加复合单位，§7.3） |
| 5 | 只有清单式 | 增加 `pricing_mode = LIST / PACKAGE` |
| 6 | 所有项目都计价 | 增加 `item_nature = INCLUDED / GIFT / OWNER_SUPPLIED` |
| 7 | 墙面面积 = 套内 × 2.55 | 优先用 `周长 × 层高 − 门窗半 − 家具`，无层高时退回系数 |
| 8 | 无最低计量 | 增加 `min_qty` 规则表（§4.2 共 8 条） |
| 9 | 无附加费 | 增加超高（>3500mm）、超层（无电梯按层）、远程（2%/县城 5%）、税金 5.36% |
| 10 | `waste_rate` 取 10~12% | 地板/吊顶 5%，瓷砖 8%，涂料 10% |

**回归基准不变**：清空企业报价时，9 个板块的合计仍必须等于现在 `BudgetPage.tsx` 的 6 项输出总额。
因为 9 个板块是 6 个分项的细分，`budget_reference_bands` 里把细分项的基准加回去即可对上。

## 10. 建议的实施顺序

```
第 1 步  V20 迁移只加 unit_kind / item_nature / min_qty 三张基础表
         先把「单位治理」和「最低计量」做掉 —— 这两项不改算法也能提升准确率
第 2 步  板块细分（6 → 9）与 budget_reference_bands 重写
         验收：无报价时总额与今天一致
第 3 步  材料/人工分离计价
         验收：GROUND 板块能拆出 materialCost 与 laborCost
第 4 步  套餐模式（PACKAGE）
         验收：90㎡ 和 60㎡ 输入得到相同基础价（最低 90㎡ 兜底生效）
第 5 步  附加费与税金
         验收：层高 3800mm 时出现超高项；无电梯时上楼费按实际层数
```

第 1 步单独就能上线，且不依赖任何报价数据——这是当前投入产出比最高的一步。
